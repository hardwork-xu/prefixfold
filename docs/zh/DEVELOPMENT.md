# 开发记录

[English](../en/DEVELOPMENT.md) · [主页](../../README_zh.md)

我将本项目作为聚焦的数值系统项目维护。此记录描述 2026-09-21 实际执行的活动，不暗示数月研发、既有部署、论文发表，或后续维护者已经完成源码学习。

## 决策与实际修复

工作区为空，因此在独立目录创建仓库。环境检查确认 M1 Pro、16 GiB 内存、Python 3.12.2、Clang 和 Metal。选择 CPU 实验；本机缺少 Docker，模型站点下载探测失败。PyPI 下载和已登录 GitHub 账户 API 可用。公开记录不包含本地路径与私人邮箱。

数值与性能契约在计时前提交。文献核查确认核心分解和分组机制来自 Cascade Attention 与 Hydragen；项目将其描述为已有机制复现和 CPU 工程实现，不宣称新算法。

首次可编辑安装发生在包文件写入前，因此无法导入 `prefixfold`；源码写入后重装本地包修复。首次静态检查发现 NumPy 形状类型推断不匹配，添加显式 NDArray 注解修复。这些是实际开发错误，不是跳过的检查。

首轮测试为 117 项通过、2 项失败，原因是行索引列表未被接受。API 随后有意扩展为接受整数序列，同时保留严格的类型、范围和唯一性检查。未放宽数值容差或删除有效断言。

独立审查发现，极大但无效的后缀填充可能在掩码之前令 BLAS 溢出。`load_suffix` 现在验证后清零未使用容量，并以真实数值回归测试覆盖。另一项审查发现早期关闭分组会同时改变后缀批处理；最终实现保持后缀执行一致，仅关闭共享前缀分组。测试直接验证前缀弱引用释放及并发读写。

直接调用 `pytest` 时一度无法导入根目录基准模块，而 `python -m pytest` 可用。pytest 配置现显式包含仓库根目录，两种入口均可执行。

## 最终资源与证据加固

最终 NumPy 分配审查发现，B=D=1 时，int64 token 索引、布尔掩码及已有 float32 分数可能同时需要 `13T` 字节，超过旧公式的 `12T` 主项。估算现采用 `4B(4T+8D+32)` 并相应缩小分块。百万 token、8 MiB 预算测试跟踪实际 NumPy 分配，并为 Python 开销保留固定余量；这不是 RSS 测试。分析器现拒绝不完整或错误标注通过的记录，README 更新改为显式操作。此检查点最终完整本地测试为 **181 项通过**；`70e7ed5` 提交正文误写为 180，此处更正且不改写历史。

## 结果与验证

首次实验保留七个场景、四种实现的全部 840 次计时，K/V 数组减少 90.91%，计算中位数加速 2.99 倍。资源估计修复后，在 `70e7ed5` 上完整重跑主实验和分块实验；最终主场景为 3.50 倍（7.1603 / 2.0437 ms），K/V 减少仍为 90.91%。两个实验会话均保留。实际分块和数值内核未变，因此不能将会话间延迟差异归因于资源估计修复。无前缀、单请求和短前缀退化仍公开保留。主实验后的分块敏感性分析使用单独记录且一致的输入，不改变原始默认值或目标。

[本地验收](../../results/acceptance.json)记录命令、退出状态、日志和源码哈希，包括干净环境安装 wheel。[实验文档](EXPERIMENTS.md)明确计时与内存口径；[发布文档](RELEASE.md)区分本地验证和外部发布、CI。

首次完整本地验收发现 Matplotlib 生成的 SVG 含行末空白。绘图输出现在规范化空白，不改变图形或测量。失败检查及原日志保留于 `results/validation-first/`；最终验收为 21 项通过、0 项失败、0 项跳过，以及 2 项本地 Docker 检查未执行。
